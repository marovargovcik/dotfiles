# system/

Version-controlled copies of the hand-written configuration that lives **outside
`$HOME`**, which `stow` therefore cannot manage. Restoring a machine from this
repo alone is not enough without these files — the ACPI lid handling, idle
suspend, sudo grants, DNS, and gnome-keyring unlock all live here.

**`system/` is not a stow package.** Do not run `stow system`. If you use
`stow */` to link everything, exclude it: `stow $(ls -d */ | grep -v system)`.

## Contents

| Path | What it is |
|---|---|
| `etc/acpi/handler.sh` | ACPI event handler — lid close/open, power button, sleep button. Writes `/run/acpi-lid-state` and locks via swaylock. |
| `etc/zzz.d/suspend/00-log` | Appends a `SUSPEND` line to `/var/log/power.log` before suspend. |
| `etc/zzz.d/resume/99-log` | Appends a `RESUME` line after resume. |
| `etc/sudoers.d/wg-quick` | NOPASSWD for `wg` / `wg-quick` (verbatim copy). |
| `etc/sudoers.d/{zzz,reboot,poweroff}` | NOPASSWD for the power-menu and swayidle commands. **Reconstructed, not copied** — see below. |
| `etc/iwd/main.conf` | iwd network configuration + resolvconf integration. |
| `etc/resolvconf.conf` | Cloudflare DNS. Corrects a typo on the old machine (`resolvconf.conF`) that left the setting inert. |
| `etc/1password/custom_allowed_browsers` | Adds `firefox` to 1Password's browser-integration allowlist. |
| `etc/pam.d/system-login` | Stock Void file **plus** two `pam_gnome_keyring.so` lines (auth + session `auto_start`) and `pam_rundir.so`. |
| `user-services/turnstile-ready/run` | Per-user runit service that signals turnstile once core user services are up. |

## Caveats

**Three sudoers fragments are reconstructed, not copied.** `/etc/sudoers.d/zzz`,
`reboot` and `poweroff` are mode `0440 root:root` and were unreadable by the
user account that captured this directory. Their file sizes on the original
machine (192/162/169 bytes) exceed what is written here, so the originals almost
certainly carry comments this copy lacks. The *grants* match the documentation.
`restore.sh` runs `visudo -c` after installing them and aborts on a parse error.
To capture them properly before wiping the old machine:

```sh
sudo ./system/backup-secrets.sh /path/to/usb    # includes /etc/sudoers.d when run as root
```

**`pam.d/system-login` is a whole-file copy** of a package-managed file. If Void
changes the stock version, diff before accepting this one wholesale — the only
local additions are the `pam_gnome_keyring.so` lines.

**The Brother PPD is not captured.** `/etc/cups/ppd/Brother_DCP-1610W_series.ppd`
is generated by `lpadmin` when the queue is created; regenerate it by installing
`brother-brlaser` and reassigning the queue (see linux-setup.md → Printing).

## Usage

```sh
sudo ./system/restore.sh          # install everything above, enable services
USER_NAME=someone sudo -E ./system/restore.sh   # for a different username
```

`restore.sh` is idempotent and backs up anything it overwrites to
`<file>.pre-restore`.
